논문 · 하이브리드 PQ 키 교환의 협상 함수: 실제 클라이언트와 서버 정책의 관측

PQ 협상 점검기

이 앱은 하이브리드 PQ(X25519MLKEM768)를 켠 TLS 서버 운영자가 "켰다"가 아니라 "실제로 쓰인다"를 확인하도록, 연결 로그와 서버 설정을 논문의 판정 규칙으로 진단해 줍니다.

  1. 예시 로그를 눌러 진단 결과가 어떻게 나오는지 본다
  2. 내 서버에 접속한 -trace 로그를 붙여 넣어 진단한다
  3. 서버 그룹 설정과 버전으로 C2·CVE 위험을 점검한다

연결 로그 진단

광고한 그룹, 먼저 보낸 key share, HRR, 최종 그룹을 뽑아 "하이브리드 / PQ 누락 / 클라이언트 선호 고전 / PQ 미적용"으로 분류합니다. 도구는 이 판정을 스스로 경고하지 않습니다(논문 §6.5).

내 서버 로그 받는 법 (OpenSSL 3.5 이상 클라이언트)

세 유형으로 각각 접속해 보면 서버의 협상 함수를 알 수 있습니다. 호스트를 바꾸세요.

# C1 하이브리드 우선 + 하이브리드 key share
openssl s_client -connect 호스트:443 -groups '*X25519MLKEM768:X25519' -trace </dev/null
# C2 하이브리드 우선 + X25519 key share만 (논문에서 PQ 누락이 난 조건)
openssl s_client -connect 호스트:443 -groups 'X25519MLKEM768:*X25519' -trace </dev/null
# C3 고전 우선
openssl s_client -connect 호스트:443 -groups '*X25519:X25519MLKEM768' -trace </dev/null

서버 설정 점검

서버 구현과 그룹 설정으로, 세 유형의 클라이언트가 무엇을 받게 될지 논문 표 2·표 7 기준으로 예측합니다.

모든 판정은 이 브라우저 안에서만 실행되며 입력은 어디에도 전송되지 않습니다.

판정 규칙은 논문이 시험한 구현·버전(OpenSSL 3.5–3.6, NSS 3.120, BoringSSL, rustls 0.23.45, Go 1.26)에 근거합니다. 그 밖은 [추정]으로 표시합니다. 논문은 기본 설정 클라이언트 16개에서 C2를 찾지 못했으므로, 이 점검은 "자주 터지는 문제"보다 "켰다고 믿는 설정이 실제로 쓰이는지"를 확인하는 용도입니다.
